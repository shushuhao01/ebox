# eBox v2.8.0 代码审查报告

- **审查日期**：2026/8/7
- **审查范围**：2.7.0 之后新增功能 —— 自动升级机制（网络层 + UI 层）、标题栏红点、更新弹窗、发布自动化 workflow、版本机制
- **审查方式**：人工静态审查 + 双子代理交叉验证（2 个独立验证代理对每个问题独立复核）

---

## 1. 功能闭环（已验证）

```
开发者构建 exe → GitHub Releases 发布 vX.Y.Z
    → workflow 自动：下载 exe / 算 SHA-256 / 解析 tag 版本号 / 提取 changelog / 更新 dist/update.json 推回 main / purge CDN
    → 客户端启动 & 每 6 小时：异步拉取 manifest（时间戳破缓存）
        → 版本号 > 本地 → 标题栏红点
        → 点红点 → 更新弹窗（版本/日期/大小/日志/立即更新/以后再说）
        → 立即更新 → 进度弹窗 → SHA-256 校验 → bat 覆盖 → 重启新版本
```

端到端实测已通过：v2.7.0 → v2.7.1（发布、清单、红点、下载、覆盖、重启）。

| 1 | Major | 网络检查失败时点击更新按钮误报"当前已是最新版本"，无法区分"无更新"与"检查失败" | ✅ 已修复（v2.8.1） |

| 4 | Minor | 升级成功后 `eBox.exe.bak` 永久残留，`cleanupBackupIfNeeded` 声明后从未接线 | ✅ 已修复（v2.8.1） |
| 5 | Minor | 用户取消下载后后台仍下载完整文件并残留临时 exe，状态标志被覆盖为成功 | ✅ 已修复（v2.8.1） |
| 6 | Minor | `TDM_CLICK_BUTTON(IDOK)` 但对话框只有 IDCANCEL 按钮，依赖 comctl32 未文档化行为关闭弹窗 | ✅ 已修复（v2.8.1） |
| 7 | Minor | bat 覆盖失败/超时分支静默恢复旧版本，用户无感知"升级失败" | ✅ 已修复（v2.8.1） |

已排除误报：
- CDN 小时时间戳缓存设计无缺陷（时间戳逐小时单调递增，hour 边界必然回源取最新）
- 路径注入风险不存在（bat 全部路径双引号包裹）

## 4. 投放评估（v2.8.1 复审）

**结论：功能层面已具备投放条件（7 项已全部修复）。**

| 维度 | 状态 | 说明 |
|------|------|------|
| 核心升级闭环 | ✅ 已验证 | 发布→清单→CDN→红点→下载→校验→覆盖→重启 全链路 |
| 版本机制 | ✅ | kVerCode 单调递增正确 |
