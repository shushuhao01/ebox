# eBox 授权服务平台设计方案

> 版本：v1.0 ｜ 日期：2026-08-08 ｜ 状态：待评审
> 端口规划：后端 **3008**（Nginx 反代 80/443），管理面板随 Nginx 静态托管

---

## 1. 背景与目标

### 1.1 现状与痛点

| 问题 | 根因 |
|---|---|
| 作废的激活码客户端仍能激活/使用 | 激活码为纯离线 ECDSA 签名，客户端只验签；黑名单只存在作者 KeyGen 本地文件，客户端无从得知 |
| 换机剩余时间无法自动继承 | 纯离线下服务端不知道客户激活时间；时长制码"激活才起算"的信息在客户机器上 |
| 已用解绑次数无法跨机器传递 | 次数存旧机注册表，新机无数据 |
| 无法掌握客户在线/使用情况 | 无任何上报通道 |
| 管理靠手工、无数据分析 | KeyGen 为单机工具，无面板无统计 |

### 1.2 目标

1. **作废即时生效**：客户端周期联网校验，作废码最迟一个心跳周期内失效（默认 6 小时）。
2. **换机自动签发**：客户端一键解绑换机，服务端签发继承剩余时间与解绑次数的新换机码。
3. **在线/使用可观测**：激活、心跳、解绑全量记录，面板实时展示在线设备与趋势分析。
4. **双轨发码**：管理面板在线生成（全管控）+ 本地 KeyGen 离线生成（应急），两轨并存互不冲突。
5. **部署可运维**：与 CRM 同技术栈，宝塔 + PM2 + Nginx + MySQL 一键部署。

## 3. 激活码体系（双轨）

### 3.1 保持现有签名格式

- 激活码 = 载荷(18B) + ECDSA P-256 签名(64B)，Base32 编码，文本 `2BOX-XXXX-...`
- 载荷版本：`verMinor==8` 时长制（`[4..7]` 存有效时长秒，0=永久，激活才起算）；`verMinor<=7` 绝对到期时间戳
- **客户端只内置公钥**，离线也可验签（兜底）；**服务器持私钥**，用于面板生成码与换机码签发；**本地 KeyGen 持私钥**，用于离线应急发码

### 3.2 服务端宽容策略（双轨并存关键）

激活/心跳上报时，服务端按码查询：

| 码状态 | 处理 |
|---|---|
| 已登记（面板生成） | 走完整在线规则：状态校验、作废、绑定数、服务端解绑次数、在线统计 |
| 未登记但签名有效（KeyGen 离线码） | 按"离线码"放行：允许激活、记录设备与心跳（供统计），但不提供在线作废/换机服务；解绑次数按客户端本地逻辑 |
| 签名无效 / 已作废 / 已过期 | 拒绝或返回对应状态 |

> 说明：离线码无在线管控是双轨设计的取舍；建议正常销售一律走面板生成，KeyGen 仅应急。

## 5. API 设计（REST + HTTPS）

### 5.1 客户端接口（`/api/v1/*`，无需登录）

通用约定：
- 请求/响应均为 JSON；参数：`code`(激活码)、`machineFp`(指纹 hex)、`appVersion`、`os`、`timestamp`(客户端 Unix 秒)、`nonce`(随机串)
- 防重放：服务端缓存 `code+nonce` 10 分钟；请求均经 `express-rate-limit` 按 IP+code 限流
- 响应统一 `{ code: 0, msg, data }`；`code!=0` 为业务错误

| 接口 | 方法/路径 | 说明 |
|---|---|---|
| 激活 | `POST /api/v1/activate` | 校验码签名与状态 → 绑定设备 → 写激活流水 → 返回 `{expireType, expireAt, durationSec, bound, unbindMax, serverTime, online}` |
| 心跳 | `POST /api/v1/heartbeat` | 上报使用 → 返回 `{status: ok/revoked/expired/kicked, graceUntil, serverTime}`；未登记有效码返回 `ok` 但标记 `online:false` |
| 解绑换机 | `POST /api/v1/unbind` | 校验月度解绑次数 → 解绑设备 → **服务端私钥签发换机码**（继承剩余到期+解绑规则）→ 旧码置"已换机" → 返回换机码 |
| 状态查询 | `GET /api/v1/status?code=&machineFp=` | 客户端授权界面展示剩余时间/状态 |

**activate 业务规则**
1. 本地先验签（客户端）失败 → 直接拒绝；
2. 服务端查 `license_keys`：
   - 未登记且签名有效 → 按"离线码"放行，`online:false`；
   - 已登记 → 校验状态（作废/过期拒绝）、绑定数（绑定码仅允许 1 台在线设备）、设备指纹登记；
3. 时长制记录服务端激活时间；换机码校验 `expire_at > now`；
4. 写 `devices` + `heartbeats(action=1)`。

**heartbeat 业务规则**
- 已登记码：状态=作废 → 返回 `revoked`；过期 → `expired`；设备被踢 → `kicked`；否则更新 `last_online_at`，返回 `ok` + `graceUntil = lastHeartbeat + 宽限天数`；
- 未登记有效码：返回 `ok` + `online:false`（仅统计）。

**unbind 业务规则**
1. 仅绑定码可解绑；月度次数 `count(unbind_logs where key_id and month) >= unbind_max` 时拒绝（`unbind_max=-1` 不限、`0` 禁止）；
2. 服务端生成换机码：取原码剩余到期（时长制 = 服务端激活时间 + durationSec；换机码 = expire_at），调用服务端私钥签名生成格式 7 换机码，写入新 `license_keys`（type=2，expire_at=原剩余到期，bound=原 bound，unbind_max=原值），并记录关联；
3. 旧码状态置 `4=已换机`，旧设备置"已解绑"，写解绑/换机流水。

### 5.2 管理面板接口（`/api/admin/*`，JWT 认证）

| 模块 | 接口 |
|---|---|
| 认证 | `POST /api/admin/login`（bcrypt 校验 + JWT 7 天）、`POST /api/admin/logout`、`GET /api/admin/profile` |
| 码管理 | `POST /keys` 生成（批量、选时长/绑定/解绑/客户/批次/备注）、`GET /keys` 分页+筛选+搜索、`POST /keys/:id/revoke`、`POST /keys/:id/restore`、`POST /keys/:id/convert`（服务端签发换机码）、`GET /keys/export` CSV、`GET /keys/verify`（验一个码） |
| 客户 | `GET/POST/PUT /customers`、`DELETE /customers/:id`、`GET /customers/:id/keys` |
| 设备/在线 | `GET /devices` 分页筛选、`GET /devices/online`（last_online 在阈值内）、`POST /devices/:id/kick` |
| 统计 | `GET /stats/overview`（码/设备/在线汇总）、`GET /stats/trend?days=30`（激活/心跳趋势）、`GET /stats/distribution`（时长/来源分布）、`GET /stats/daily` |
| 心跳流水 | `GET /heartbeats` 分页 |
| 系统设置 | `GET/PUT /config`（心跳间隔/离线宽限/强制在线/公告） |
| 操作日志 | `GET /operation-logs` 分页 |
| 管理员 | `GET/POST/PUT /users`（建/改管理员，仅超管） |

### 5.3 安全

- 全站 HTTPS（宝塔免费证书）；管理接口需 JWT；密码 bcrypt(10)；
- `express-rate-limit`：客户端 API 每 IP 100 次/分 + 每 code 10 次/分；管理接口 20 次/分；
- `helmet` + CORS 白名单；`joi` 校验所有入参；操作全量写 `operation_logs`；
- 私钥仅存在服务器 `.env`（gitignore），面板页面禁用调试；防重放 nonce 缓存。

## 6. 核心业务流

### 6.1 激活（在线优先 + 离线宽限）

```
客户输入激活码 → 本地验签
 ├─ 签名失败 → 提示无效
 ├─ 联网成功 → 调 /activate
 │    ├─ 已登记码：按服务端规则通过/拒绝，写设备+流水
 │    └─ 未登记有效码：放行(online:false)
 └─ 网络失败 → 走本地宽限：上次心跳 + 宽限(7天) 内放行；超期锁定提示联网
```

### 6.2 心跳与作废生效

- 客户端启动即心跳，后台定时（默认 6h）静默心跳；服务端返回 `revoked` 时立即锁定退出；
- 作废生效时间 ≈ 作废时刻 + 心跳间隔（最长 6h，可配置 1h）；设置 `force_online_activate=1` 后激活必须在线，作废新激活立即失败。

### 6.3 换机（服务端签发）

```
客户点"解绑换机" → 客户端调 /unbind → 服务端校验次数 → 解绑旧设备
 → 服务端私钥生成换机码(继承剩余时间+解绑次数) → 返回客户端
 → 客户端展示换机码 + 一键复制 → 旧码置"已换机"，旧设备解绑
 → 客户在新机粘贴换机码激活 → 绑定新设备
```

### 6.4 踢下线（二期）

面板对指定设备 `POST /kick` → 设备下次心跳收到 `kicked` → 锁定；重复激活需重新绑定（受解绑次数约束）。

## 7. 管理面板功能与 UI（在线部署版本 · 参考 CRM，简约大方）

### 7.1 整体框架

- **布局结构**：左侧固定菜单（240px，可折叠）+ 顶部栏（面包屑/系统状态/当前用户/退出）+ 主内容区（白色卡片网格，圆角 8px + 轻阴影）；
- **主题色**：主色 `#3A7AFE`（CRM 同源蓝），成功 `#22C55E`、警告 `#F59E0B`、危险 `#EF4444`；背景 `#F3F6FB`，卡片纯白 `#FFFFFF`，正文 `#1F2937`、次要 `#6B7280`；

- **响应式**：≥1280 全宽卡片，<1280 两列，菜单可折叠成图标栏。

### 7.2 菜单结构（路由表）

### 7.3 页面构成与 UI 明细

**① 登录页 `/login`**

**② 总览 `/dashboard`（默认首页）**
- 顶部 4 个统计卡（`el-card`+`el-statistic`）：码总数 / 已用数 / 在线设备 / 今日激活，均带小图标与环比色；

**③ 激活码管理 `/licenses`（核心页）**
- 顶部工具栏：搜索框（按码/客户/指纹）+ 状态筛选（全部/可用/已用/作废/已换机）+ 类型筛选（库存/换机/在线生成）+ 批次筛选 + 日期范围 + 重置；

- **生成对话框**（`el-dialog` 宽 560px，分两步）：

- 表格列：激活码（等宽字体、复制图标）、类型 Tag、时长/到期、绑定 Tag、已解绑次数、状态 Tag（可用/已用/作废-红/已换机-橙）、所属客户、创建时间、操作（详情 / **作废-红色** / 换机）；
- **作废确认**：`ElMessageBox` 红色警告图标，文案含码尾号与后果说明，确认按钮红色"确认作废"；
- 分页（20 条/页）+ 行详情抽屉（右侧 `el-drawer`：完整码、设备列表、心跳摘要、操作时间线）。

**④ 码批次 `/batches`**
- 批次卡片列表（批次号/生成时间/数量/使用数量/创建人/状态）+ 批次详情抽屉（该批所有码及状态）；
- 删除批次需确认（仅允许未使用的批次）。

**⑤ 客户管理 `/customers`**
- 卡片网格（头像首字母 + 名称 + 联系方式 + 名下码数/在用设备数 + 最近活跃）；
- 点击进入详情页：客户信息卡 + 名下激活码表格（同码管理列）+ 设备表格（该客户所有设备 + 踢下线入口）+ 解绑/作废记录。

**⑥ 设备管理 `/devices`**
- 工具栏：在线状态筛选（在线/离线/锁定）+ 搜索（指纹/码/IP）+ 按客户筛选；
- 表格列：设备指纹（前 8 位缩写+完整 tooltip）、激活码、客户、最后在线时间、IP、系统版本、在线状态灯（绿/灰/红）、操作（**踢下线**红色 / 查看详情）；
- 踢下线二次确认（红），成功后设备下次心跳即被锁定。

**⑦ 换机记录 `/unbind-logs`**
- 表格：旧码/新码（换机码）、客户、设备旧指纹、新指纹、操作时间、结果（成功/超限/失败原因）；
- 月度解绑次数徽标（当前月已用 N 次/上限）。

**⑧ 作废记录 `/revoke-logs`**
- 表格：码、作废时间、操作人、原因、涉及设备数；顶部统计卡（本月作废数）。

**⑨ 使用分析 `/analytics`**
- 顶部日期范围选择器（近 7/30/90 天）；
- 行 1：激活/心跳双 Y 轴趋势折线 + 每日新增客户柱状图；
- 行 2：客户设备数分布直方图 + 解绑次数趋势 + 作废率环形图；
- 行 3：地区/运营商分布（按 IP 解析，可选）+ 时段活跃热力图（按小时）。

**⑩ 心跳日志 `/heartbeats`**
- 筛选：动作（activate/heartbeat/unbind/status）+ 状态（成功/拒绝）+ 时间范围；
- 表格：时间、激活码、设备指纹、IP、动作 Tag、结果 Tag、响应毫秒；分页 + 详情 tooltip。

**⑪ 系统设置 `/settings`**
- 选项卡（`el-tabs`）：
  - 授权策略：心跳间隔（1~24h 滑杆）、离线宽限天数（1~30）、强制在线开关、发码类型默认值；
  - 账号安全：管理员改密、登录 IP 白名单、登录失败锁定阈值；
  - 站点公告：公告内容（客户端激活弹窗展示）、维护模式开关；
  - 数据：数据库备份说明、导出全部数据按钮。

**⑫ 操作日志 `/logs`**
- 表格：时间、操作人、模块、动作、详情（JSON 摘要）、IP；按模块/操作人筛选；导出 CSV。

### 7.4 全局交互规范

- 所有写操作（作废/踢下线/删除）一律二次确认且确认按钮为红色；
- 复制操作统一用"复制图标 + 成功 Toast"；激活码等长文本用等宽字体；

## 9. 宝塔部署方案

| 步骤 | 说明 |
|---|---|
| 1. 环境 | 宝塔装 Node.js ≥22、MySQL 8、PM2；创建站点 `ebox-license.你的域名.com`，申请 SSL |
| 2. 数据库 | 导入 `database/schema.sql`，创建 `license_server` 库与专用账号 |
| 3. 后端 | 上传 `license-server/backend`，`npm i && npm run build`，配置 `.env`（含数据库连接、JWT 密钥、私钥、端口 3008） |
| 4. PM2 | `pm2 start ecosystem.config.js`，`pm2 save && pm2 startup` |
| 5. 前端 | 上传 `license-server/admin` 构建产物到站点根目录 `/admin`，Nginx 反代 `/api` → `127.0.0.1:3008` |
| 6. 更新 | `update.sh`：拉代码 → 构建 → 重启 PM2（对齐 CRM 的 update.sh 写法） |
| 7. 初始化 | `npm run init:admin` 创建首个管理员；`npm run gen:key` 生成/回填服务端私钥 |

**Nginx 关键配置**
```nginx
server {
  listen 443 ssl;
  server_name ebox-license.example.com;
  # ... ssl 证书配置 ...
  location /api/ {
    proxy_pass http://127.0.0.1:3008;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_http_version 1.1;
  }
  location / { root /www/wwwroot/ebox-license/admin; try_files $uri $uri/ /index.html; }
}
```

## 11. 风险与注意

| 风险 | 应对 |
|---|---|
| 私钥泄露 | 私钥只入服务器 `.env` 与本地 KeyGen，gitignore 排除；服务器文件权限 600；泄露即换公钥并重启客户端版本 |
| 心跳被客户端绕过 | 客户端为自有程序，防破解靠签名+混淆+进程保护；管控强度与离线宽限相平衡 |
| 客户断网 | 宽限 7 天可配置；面板可查离线超期设备 |
| 时钟篡改 | 心跳以服务端时间为准下发 `graceUntil`；客户端时间偏移过大（>5 分钟）标记异常 |
| 单点故障 | 宝塔服务器崩溃影响在线校验，但本地宽限保证短期可用；建议服务器异机备份数据库 |
